## Deployment Model
### Frontend
- Hosted on Vercel
- Uses same-origin proxying through Next.js route handler at `/api/v1/[...path]`
- Browser should call the frontend origin, not Railway directly, for normal app traffic

### Backend
- Hosted on Railway
- Runs Alembic on deploy, then starts FastAPI via Uvicorn

### Important environment variables
- Vercel:
  - `API_PROXY_TARGET=https://schoolmanagmentsystem-production.up.railway.app`
- Railway:
  - `FRONTEND_URL=https://school-managment-system-dee11.vercel.app`
  - `ALLOWED_ORIGINS=https://school-managment-system-dee11.vercel.app`
  - `DATABASE_URL=<real postgres url>`
  - `SECRET_KEY=<jwt secret>`
  - `REFRESH_SECRET_KEY=<refresh secret>`

### Important deploy rule
- `API_PROXY_TARGET` must be the backend origin only
- Do not append `/api/v1`
- Do not use `localhost` in production
- Do not expose a public `NEXT_PUBLIC_*` API URL unless intentionally changing the architecture

## Authentication Architecture
### Frontend auth behavior
- Tokens are stored in cookies:
  - `access_token`
  - `refresh_token`
  - `user_role`
- Frontend also sends `Authorization: Bearer <token>` on API requests
- The Next.js proxy forwards requests from Vercel to Railway

### Important auth fixes already made
- Cookie path was corrected so auth works across all routes, not just `/login`
- Proxy redirect handling was fixed so auth survives FastAPI trailing-slash redirects
- Frontend role sync was improved to stop relying on stale role state alone

### Meaning of common errors
- `401 Unauthorized`:
  authentication/token/session problem
- `403 Forbidden`:
  authenticated, but blocked by role/permission

### Known browser noise that is not the app bug
These messages were seen during debugging and are not the root cause:
- `SES Removing unpermitted intrinsics`
- `Unchecked runtime.lastError: Could not establish connection`
- MetaMask extension errors
